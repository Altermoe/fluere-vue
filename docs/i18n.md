# 文档站 i18n 文案规范（Internationalization）

> 状态：已落地。界面串双语言（`@nuxtjs/i18n`，`zh-Hans` 为主语言）+ `scripts/i18n-check.mjs` 阻断式检查。
> 背景事故（2026-10-13）：首页 CTA 文案在写包名 `@fluere-vue/ui` 时，裸 `@` 被 vue-i18n 当作 **linked message** 语法，`/` 与 `/en` 直接 500（`Message compilation error: Invalid linked format`）；而 `pnpm check` 全绿——**它不编译消息**。本文把该类消息语法坑与验证方式固化成规范。

## 1. 适用面与关键文件

| 内容           | 位置                                                   | 备注                                                          |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| 文档站界面串   | `apps/docs/i18n/locales/{zh-Hans,en}.json`             | 主语言 `zh-Hans`；`en` 为同构回退                             |
| 文档站正文     | `apps/docs/content/{zh-Hans,en}/**`                    | 不走 i18n key，走 content collection                          |
| 类型 schema    | `apps/docs/i18n/schema.ts`                             | `MessageSchema` 由 `zh-Hans.json` 推导，key 写错 vue-tsc 报错 |
| 组件库内置文案 | `packages/ui/src/**/locale.ts`                         | `zhHans` / `en` 两侧 key 集必须一致，回退链 `zh-Hans→zh→en`   |
| 阻断式检查     | `scripts/i18n-check.mjs`（`pnpm i18n:check`，接入 CI） | 能查 / 查不了什么见 §4                                        |

## 2. 铁律

1. **文案一律走 key**：`apps/docs` 的 `pages/` / `layouts/` / `components/` / `composables/` / `data/` / `plugins/` / `utils/` 下不得出现硬编码中文界面串（检查脚本剥离注释后扫描；确有必要的例外进 `scripts/i18n-check.mjs` 的 `HARDCODED_ALLOW` 并写清理由）。
2. **key 集合以 `zh-Hans` 为准**：`en` 缺 key 会在运行期静默回退中文，多 key 是孤儿串——两侧必须与主语言完全一致。
3. **`t()` / `tm()` 的 key 必须真实存在**：vue-tsc 不校验 key，写错时页面会渲染出 key 路径本身（纯 ASCII，中文扫描拦不住）。
4. **组件库 locale 切片两侧 key 必须一致**：否则回退链在某侧断链（静态校核只解析顶层属性名，切片保持一层扁平）。

## 3. 消息语法：特殊字符必须转义（本次踩的坑）

vue-i18n 的 message **不是纯文本**：`{` `}` `@` `|` `$` 都有语法含义（插值 / linked message / 复数分隔符 / linked key 修饰符）。要**原样输出**这些字符，必须用「字面量插值」把字符写成 `{'x'}`：

```jsonc
{
  // ✓ 输出：安装 @fluere-vue/ui 与 vue，引入样式。
  "home.ctaCards.install.desc": "安装 {'@'}fluere-vue/ui 与 vue，引入样式。",
}
```

| 字面量 | 转义写法 | 不转义的后果                                                      |
| ------ | -------- | ----------------------------------------------------------------- |
| `@`    | `{'@'}`  | **编译报 `Invalid linked format` → SSR / 预渲染 500**（本次事故） |
| `{`    | `{'{'}`  | 编译报 `Unterminated closing brace`                               |
| `}`    | `{'}'}`  | 编译报 `Unbalanced closing brace`                                 |

`|` 与 `$` 分别被当作复数分隔符与 linked key 修饰符前缀，原样输出时同样写成 `{'|'}` / `{'$'}`。

> 典型触发场景：文案里写包名（`@fluere-vue/ui` 这类 scope 包）、`@media`、花括号占位示例、邮箱或社交 handle。

## 4. `pnpm check` 拦不住消息语法错（关键认知）

`scripts/i18n-check.mjs` 只做三件事：**key 集合一致、硬编码中文扫描、`t()`/`tm()` 引用存在性**——**它不编译消息**。消息编译只发生在：

- `@nuxtjs/i18n` 客户端预编译（`@intlify/unplugin-vue-i18n`，dev 下 HMR 重编）；
- SSR 运行期 `getMessage`；
- `nuxt generate` 预渲染。

因此裸 `@` 能通过 `pnpm i18n:check` 与 `pnpm check`，却让页面 500。

**规范：改完 i18n 文案，除了 `pnpm check`，必须让消息真正编译一次。**

```bash
# ① 起 dev server（自己起，别占用用户前台进程，见 AGENTS.md《验证与环境操作》）
cd apps/docs && nohup pnpm dev > temp/docs-dev.log 2>&1 &
# ② 首页文案改动时，两语种都要 200
curl -sS -o /dev/null -w 'zh-Hans %{http_code}\n' http://localhost:60727/
curl -sS -o /dev/null -w 'en      %{http_code}\n' http://localhost:60727/en
# ③ 或直接预渲染，会编译全部消息
pnpm docs:generate
```

## 5. 复现与验证（证据）

用本仓 `@intlify/message-compiler` 的 `baseCompile` 直接编译字符串（无需起服务，在仓库根目录执行）：

```bash
node --input-type=module <<'EOF'
import { baseCompile } from './node_modules/.pnpm/@intlify+message-compiler@11.4.13/node_modules/@intlify/message-compiler/dist/message-compiler.mjs'
const samples = [
  '安装 @fluere-vue/ui 与 vue。',
  "安装 {'@'}fluere-vue/ui 与 vue。",
  'a { b',
  "a {'{'} b",
  'a } b',
  "a {'}'} b",
]
for (const msg of samples) {
  const errors = []
  baseCompile(msg, { onError: (e) => errors.push(e.message.split('\n')[0]) })
  console.log(errors.length ? `✗ ${errors[0]}  ← ${JSON.stringify(msg)}` : `✓ ${JSON.stringify(msg)}`)
}
EOF
```

预期输出（2026-10-13 实测）：

```text
✗ Invalid linked format  ← "安装 @fluere-vue/ui 与 vue。"
✓ "安装 {'@'}fluere-vue/ui 与 vue。"
✗ Unterminated closing brace  ← "a { b"
✓ "a {'{'} b"
✗ Unbalanced closing brace  ← "a } b"
✓ "a {'}'} b"
```

> 路径里的 `.pnpm/@intlify+message-compiler@11.4.13` 带版本号；升级依赖后用 `ls node_modules/.pnpm | grep message-compiler` 取实际路径。

## 6. 新增 / 修改文案自检清单

- [ ] 未在 `apps/docs` 的扫描目录里新增硬编码中文
- [ ] `t()` / `tm()` 引用的是存在的 key
- [ ] `pnpm i18n:check` 通过
- [ ] **消息真实编译过一次**：dev server 两语种 200，或 `pnpm docs:generate` 通过（§4）
